# 01 - SQL


1. 데이터베이스는 표입니다

Day 12 까지는 데이터를 두 곳에 뒀습니다.

  products.json    파일에 적어둔 것. 읽기만 했습니다
  localStorage     브라우저에 적어둔 것. 그 브라우저에만 남습니다

둘 다 한계가 같습니다. 내 컴퓨터를 벗어나지 못합니다.
다른 사람이 내 장바구니를 볼 수 없고, 내가 폰으로 접속하면 빈 장바구니입니다.

데이터베이스는 서버에 있습니다. 그래서 누가 접속하든 같은 데이터를 봅니다.
생긴 건 엑셀 표와 똑같습니다.

  products 표

  ┌────┬────────────────────────┬──────────┬────────┬───────┬───────┐
  │ id │ name                   │ brand    │ kind   │ price │ stock │
  ├────┼────────────────────────┼──────────┼────────┼───────┼───────┤
  │ 1  │ 모나미 153 볼펜 0.7    │ 모나미   │ 필기구 │ 600   │ 9     │
  │ 2  │ 제브라 사라사 클립     │ 제브라   │ 필기구 │ 1800  │ 5     │
  │ 3  │ 옥스포드 스프링노트 A5 │ 옥스포드 │ 노트   │ 3400  │ 6     │
  └────┴────────────────────────┴──────────┴────────┴───────┴───────┘

가로 한 줄을 행(row), 세로 한 칸을 열(column) 이라고 부릅니다.
JSON 으로 보면 이렇게 생긴 것과 같습니다.

  { "id": 1, "name": "모나미 153 볼펜 0.7", "brand": "모나미", ... }

그러니까 products.json 의 배열 하나가 표 하나입니다. 모양은 이미 아는 것입니다.
달라지는 건 **꺼내는 방법**입니다. JS 에서는 filter 와 sort 로 걸렀지만
여기서는 SQL 이라는 말로 "뭘 달라" 고 적어서 보냅니다.

  JS    products.filter(p => p.kind === "노트")
  SQL   SELECT * FROM products WHERE kind = '노트'

읽어보면 거의 같은 말입니다. SQL 은 **어떻게 찾을지**를 안 적습니다.
무엇을 원하는지만 적고, 찾는 방법은 데이터베이스가 알아서 정합니다.


2. 돌려보는 방법 ⭐

이 컴퓨터에는 XAMPP 가 깔려 있습니다. 안에 MariaDB 가 들어 있습니다.
MariaDB 는 MySQL 에서 갈라져 나온 것이라 쓰는 말이 거의 같습니다.
교재에 MySQL 이라고 써 있으면 그대로 따라하면 됩니다.

  PHP        8.2.12
  MariaDB    10.4.32
  설치 위치  C:\xampp

먼저 켜야 합니다. XAMPP Control Panel 에서 MySQL 줄의 Start 를 누릅니다.
켜지면 글자가 초록색이 되고 포트 3306 이 뜹니다.

켠 다음 두 가지 방법으로 쓸 수 있습니다.

  방법 1 - 명령창 (연습은 이게 빠릅니다)

    C:\xampp\mysql\bin\mysql.exe -u root

  비밀번호는 기본값이 없습니다. 그냥 엔터입니다.
  들어가면 프롬프트가 MariaDB [(none)]> 로 바뀝니다.
  나올 때는 exit 또는 quit 입니다.

  한 줄만 실행하고 바로 나오고 싶으면 -e 를 씁니다.

    C:\xampp\mysql\bin\mysql.exe -u root -e "SHOW DATABASES;"

  방법 2 - phpMyAdmin (눈으로 보기 편합니다)

    Apache 도 Start 하고 브라우저에서     http://localhost/phpmyadmin

  표를 눈으로 보면서 고칠 수 있습니다. 다만 대회에서는 SQL 을 직접 써야 하니
  연습은 명령창으로 하는 게 낫습니다.

⚠️ SQL 문장은 세미콜론으로 끝납니다. 안 찍으면 엔터를 쳐도 실행되지 않고
   -> 표시가 나오면서 계속 기다립니다. 그때 세미콜론을 찍고 엔터를 누르면 됩니다.


3. 데이터베이스 만들기

데이터베이스 안에 표들이 들어갑니다. 폴더와 파일 같은 관계입니다.

  CREATE DATABASE stationery
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

  USE stationery;

utf8mb4 를 꼭 써야 합니다. 안 쓰면 한글이 ??? 로 깨집니다.
뒤의 mb4 는 4바이트까지 받는다는 뜻이고, 이모지도 들어갑니다.
utf8 만 쓰면 MySQL 에서는 3바이트까지만 받아서 이모지가 깨집니다.

COLLATE 는 글자를 비교하는 규칙입니다. _ci 는 case insensitive,
대소문자를 구분하지 않는다는 뜻입니다. Day 12 에서 검색할 때
toLowerCase() 를 양쪽에 걸었던 그 일을 데이터베이스가 알아서 해줍니다.

  USE stationery;    앞으로 이 데이터베이스를 쓴다는 선언

USE 를 안 하면 표를 만들 때마다 stationery.products 처럼 앞에 붙여야 합니다.

  SHOW DATABASES;          데이터베이스 목록
  SHOW TABLES;             지금 데이터베이스의 표 목록
  DESC products;           products 표의 구조
  DROP DATABASE stationery;   통째로 지운다 (되돌릴 수 없습니다)


4. 자료형

열마다 "여기엔 이런 값만 들어온다" 를 미리 정해둡니다.
JS 변수와 다른 점입니다. 숫자 칸에 글자를 넣으려 하면 데이터베이스가 막습니다.

  ┌───────────────┬──────────────────────┬───────────────────────────┐
  │ 자료형        │ 담는 것              │ 쓰는 곳                   │
  ├───────────────┼──────────────────────┼───────────────────────────┤
  │ INT           │ 정수 약 ±21억        │ id, 수량, 가격(원 단위)   │
  │ BIGINT        │ 더 큰 정수           │ 조회수, 금액이 아주 클 때 │
  │ TINYINT       │ -128 ~ 127           │ 0/1 참거짓, 작은 상태값   │
  │ DECIMAL(10,2) │ 소수를 정확하게      │ 돈, 비율                  │
  │ DOUBLE        │ 소수 (오차 있음)     │ 좌표, 측정값              │
  │ VARCHAR(n)    │ 글자 n 개까지        │ 이름, 아이디, 제목        │
  │ TEXT          │ 긴 글 (약 65KB)      │ 본문, 메모                │
  │ DATE          │ 2026-11-10           │ 생일, 대여일              │
  │ DATETIME      │ 2026-11-10 22:30:00  │ 가입 시각, 주문 시각      │
  │ TIMESTAMP     │ DATETIME + 자동 갱신 │ 수정 시각                 │
  │ ENUM('a','b') │ 정해둔 것 중 하나    │ 상태, 등급                │
  └───────────────┴──────────────────────┴───────────────────────────┘

⚠️ 돈에 DOUBLE 을 쓰지 마세요. 0.1 + 0.2 가 0.30000000000000004 가 되는
   그 문제가 데이터베이스에서도 똑같이 생깁니다. DECIMAL 을 쓰거나,
   아니면 원 단위 정수(INT)로 저장하세요. 우리는 INT 로 가겠습니다.

VARCHAR(n) 의 n 은 바이트가 아니라 글자 수입니다. VARCHAR(10) 에
한글 10글자가 들어갑니다. 넘치면 잘리는 게 아니라 거부됩니다.

TEXT 와 VARCHAR 의 차이는 길이만이 아닙니다. TEXT 는 인덱스를 걸 때
제약이 있고 정렬이 느립니다. 65535 자가 필요 없으면 VARCHAR 를 쓰세요.


5. 제약 - 잘못된 값이 못 들어오게 막기 ⭐⭐

Day 11 에서 폼 검증을 했습니다. required, min, pattern 같은 것들이요.
그건 **브라우저**에서 막은 겁니다. 개발자도구로 속성을 지우면 뚫립니다.
제약은 **데이터베이스**에서 막습니다. 어떻게 보내도 안 뚫립니다.

  ┌────────────────┬──────────────────────────────────────────────────┐
  │ 제약           │ 뜻                                               │
  ├────────────────┼──────────────────────────────────────────────────┤
  │ PRIMARY KEY    │ 이 행을 가리키는 유일한 값. 중복 불가, NULL 불가 │
  │ AUTO_INCREMENT │ 넣을 때 1, 2, 3 ... 자동으로 번호를 매긴다       │
  │ NOT NULL       │ 비워둘 수 없다                                   │
  │ DEFAULT 값     │ 안 넣으면 이 값이 들어간다                       │
  │ UNIQUE         │ 같은 값이 두 번 들어올 수 없다                   │
  │ FOREIGN KEY    │ 다른 표에 있는 값만 들어올 수 있다               │
  │ CHECK (조건)   │ 조건을 만족하는 값만 들어올 수 있다              │
  └────────────────┴──────────────────────────────────────────────────┘

PRIMARY KEY 와 UNIQUE 의 차이는 하나뿐입니다. PRIMARY KEY 는 표에 하나만
둘 수 있고 NULL 을 못 받습니다. UNIQUE 는 여러 개 둘 수 있고 NULL 은 받습니다.

Day 12 에서 "id 는 겹치지 않게 두세요. 즐겨찾기를 id 로 저장하니까
id 가 같은 항목이 둘 있으면 하나만 눌러도 둘 다 켜집니다" 라고 했었죠.
그걸 사람이 조심하는 대신 데이터베이스가 막아주는 게 PRIMARY KEY 입니다.


6. 우리가 쓸 표 네 개

Day 12 의 문구점 장바구니를 서버로 옮긴 모양입니다.
장바구니를 "주문" 으로 확정해서 저장합니다.

  members        회원
  products       상품        <- Day 12 의 products.json 과 같은 모양
  orders         주문 한 건
  order_items    그 주문에 담긴 상품들

관계는 이렇습니다.

  members 1 ────< orders 1 ────< order_items >──── 1 products

  회원 한 명이 주문을 여러 번 한다          (1 : N)
  주문 한 건에 상품이 여러 개 담긴다        (1 : N)
  같은 상품이 여러 주문에 담긴다            (N : 1)

order_items 가 orders 와 products 사이에 끼어 있습니다.
"주문 3번에 2번 상품이 4개" 같은 줄이 여기 들어갑니다.
Day 12 에서 localStorage 에 { id, qty } 만 저장했던 것과 같은 생각입니다.
상품 이름과 가격을 복사해두지 않고 product_id 만 적습니다.

  CREATE TABLE members (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    login_id  VARCHAR(20)  NOT NULL UNIQUE,
    name      VARCHAR(30)  NOT NULL,
    phone     VARCHAR(13),
    joined_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
  );

  CREATE TABLE products (
    id     INT AUTO_INCREMENT PRIMARY KEY,
    name   VARCHAR(60) NOT NULL,
    brand  VARCHAR(20) NOT NULL,
    kind   VARCHAR(20) NOT NULL,
    price  INT         NOT NULL,
    stock  INT         NOT NULL DEFAULT 0
  );

  CREATE TABLE orders (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    member_id  INT      NOT NULL,
    ordered_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    status     ENUM('담김','결제','배송','취소') NOT NULL DEFAULT '담김',
    FOREIGN KEY (member_id) REFERENCES members(id)
  );

  CREATE TABLE order_items (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    order_id   INT NOT NULL,
    product_id INT NOT NULL,
    qty        INT NOT NULL,
    price      INT NOT NULL,
    FOREIGN KEY (order_id)   REFERENCES orders(id)   ON DELETE CASCADE,
    FOREIGN KEY (product_id) REFERENCES products(id)
  );

order_items 에 price 가 또 있는 게 이상해 보일 겁니다. products 에 이미 있는데요.
일부러 넣은 것입니다. **주문한 순간의 가격**을 적어둬야 하기 때문입니다.
가격이 나중에 오르면 옛날 주문의 금액까지 바뀌어 버립니다.

Day 12 의 "저장값에 이름·가격을 복사하지 마세요" 와 반대로 보이지만 다릅니다.
장바구니는 **지금** 가격으로 계산해야 하고, 주문은 **그때** 가격으로 남겨야 합니다.


7. INSERT - 넣기

  INSERT INTO products (name, brand, kind, price, stock)
  VALUES ('모나미 153 볼펜 0.7', '모나미', '필기구', 600, 9);

열 이름을 적고, 그 순서대로 값을 적습니다.
id 는 AUTO_INCREMENT 라서 안 적습니다. 알아서 붙습니다.
stock 도 DEFAULT 0 이 있으니 생략할 수 있습니다.

여러 줄을 한 번에 넣을 수 있습니다. 한 줄씩 넣는 것보다 훨씬 빠릅니다.

  INSERT INTO products (name, brand, kind, price, stock) VALUES
    ('모나미 플러스펜 3000',    '모나미',     '필기구', 800,   7),
    ('제브라 사라사 클립 JJ15', '제브라',     '필기구', 1800,  5),
    ('파버카스텔 색연필 24색',  '파버카스텔', '필기구', 18000, 2),
    ('옥스포드 스프링노트 A5',  '옥스포드',   '노트',   3400,  6),
    ('포스트잇 떡메모지 100매', '포스트잇',   '노트',   1200,  0);

⚠️ 문자열은 홑따옴표입니다. 쌍따옴표도 되긴 하지만 홑따옴표가 표준입니다.
   숫자에는 따옴표를 붙이지 마세요. price 에 '600' 을 넣으면 들어가긴 하는데
   비교할 때 이상하게 동작합니다.

열 이름을 생략할 수도 있습니다. 하지만 쓰지 마세요.

  INSERT INTO products VALUES (NULL, '이름', '브랜드', '분류', 600, 9);

표에 열이 하나 추가되는 순간 이 문장은 전부 깨집니다. 열 이름을 적으면 안 깨집니다.


8. SELECT 와 WHERE - 꺼내기 ⭐⭐⭐

가장 많이 쓰는 문장입니다.

  SELECT *             FROM products;                   모든 열, 모든 행
  SELECT name, price   FROM products;                   두 열만
  SELECT DISTINCT kind FROM products;                   kind 의 종류만 (중복 제거)
  SELECT name AS 상품명, price AS 가격 FROM products;    이름을 바꿔서 받기

* 는 편하지만 실제 코드에서는 열을 적는 게 낫습니다.
안 쓰는 열까지 다 끌고 오고, 열 순서가 바뀌면 코드가 깨집니다.

WHERE 로 조건을 겁니다.

  ┌─────────────────┬──────────────────────┬─────────────────────────────┐
  │ 조건            │ 뜻                   │ 예                          │
  ├─────────────────┼──────────────────────┼─────────────────────────────┤
  │ =               │ 같다                 │ kind = '노트'               │
  │ <> 또는 !=      │ 다르다               │ kind <> '노트'              │
  │ > < >= <=       │ 크다 작다            │ price >= 1000               │
  │ BETWEEN a AND b │ a 이상 b 이하        │ price BETWEEN 1000 AND 5000 │
  │ IN (a, b, c)    │ 이 중 하나           │ kind IN ('노트','파일')     │
  │ NOT IN (...)    │ 이 중에 없다         │ kind NOT IN ('노트')        │
  │ LIKE '%볼펜%'   │ 포함한다             │ name LIKE '%볼펜%'          │
  │ LIKE '모나미%'  │ 로 시작한다          │ name LIKE '모나미%'         │
  │ LIKE '_나미%'   │ _ 는 아무 글자 한 개 │ name LIKE '_나미%'          │
  │ IS NULL         │ 비어 있다            │ phone IS NULL               │
  │ IS NOT NULL     │ 값이 있다            │ phone IS NOT NULL           │
  │ AND OR NOT      │ 조건 묶기            │ price > 1000 AND stock > 0  │
  └─────────────────┴──────────────────────┴─────────────────────────────┘

  SELECT name, price FROM products
  WHERE kind = '필기구' AND price <= 2000 AND stock > 0;

Day 12 에서 이렇게 썼던 것과 같은 일입니다.

  copy.filter(e => e.kind === kind.value)
  copy = copy.filter(e => e.stock > 0)

filter 를 세 번 이어 붙였던 걸 WHERE 한 줄에 AND 로 적습니다.

⚠️ AND 와 OR 를 섞을 때는 괄호를 치세요. AND 가 OR 보다 먼저 묶입니다.

  WHERE kind = '노트' OR kind = '파일' AND stock > 0

이건 "노트 전부" 또는 "파일 중 재고 있는 것" 입니다. 아마 원한 건 이거겠죠.

  WHERE (kind = '노트' OR kind = '파일') AND stock > 0

LIKE 에서 % 는 "아무 글자 몇 개든" 입니다. JS 의 includes 와 같은 일을 하려면
앞뒤에 % 를 붙입니다. 앞에 % 가 붙으면 인덱스를 못 쓰니 느립니다 (17번 참고).


9. ORDER BY 와 LIMIT - 정렬과 페이지

  SELECT * FROM products ORDER BY price ASC;         싼 것부터 (ASC 는 생략 가능)
  SELECT * FROM products ORDER BY price DESC;        비싼 것부터
  SELECT * FROM products ORDER BY kind, price DESC;  분류별로 묶고 그 안에서 비싼 것부터

Day 12 의 정렬 네 가지가 그대로 됩니다.

  기본순        ORDER BY id
  이름순        ORDER BY name
  싼 것부터     ORDER BY price
  비싼 것부터   ORDER BY price DESC

LIMIT 으로 개수를 자릅니다.

  SELECT * FROM products ORDER BY price DESC LIMIT 5;             비싼 것 5개
  SELECT * FROM products ORDER BY id LIMIT 10 OFFSET 20;          21번째부터 10개

OFFSET 이 페이지 넘기기입니다. 한 페이지에 10개면

  1페이지  LIMIT 10 OFFSET 0
  2페이지  LIMIT 10 OFFSET 10
  3페이지  LIMIT 10 OFFSET 20

  OFFSET = (페이지번호 - 1) * 개수

⚠️ ORDER BY 없이 LIMIT 을 쓰면 **어떤 행이 나올지 보장되지 않습니다.**
   표에 순서라는 개념이 없기 때문입니다. 지금 잘 나오는 것처럼 보여도
   데이터가 많아지거나 인덱스가 바뀌면 순서가 달라집니다.
   LIMIT 을 쓸 거면 ORDER BY 를 같이 쓰세요.


10. UPDATE 와 DELETE ⭐ 조심해야 하는 두 문장

  UPDATE products SET price = 700 WHERE id = 1;
  UPDATE products SET price = price + 100, stock = stock - 1 WHERE id = 1;
  DELETE FROM products WHERE id = 1;

SET 에서 price = price + 100 처럼 **원래 값을 써서** 계산할 수 있습니다.
JS 에서 `already.qty++` 했던 것과 같습니다.

⚠️⚠️ WHERE 를 빼먹으면 **전부** 바뀝니다.

  UPDATE products SET price = 700;    모든 상품 가격이 700원이 됩니다
  DELETE FROM products;               모든 상품이 사라집니다

되돌릴 수 없습니다. 실수로 이걸 하는 사람이 정말 많습니다.
습관을 하나 만들어 두세요 - **지우기 전에 같은 WHERE 로 SELECT 를 먼저 해봅니다.**

  SELECT * FROM products WHERE id = 1;   <- 이게 맞나 눈으로 확인
  DELETE  FROM products WHERE id = 1;    <- 그 다음 지운다

명령창에서 아예 막아둘 수도 있습니다.

  C:\xampp\mysql\bin\mysql.exe -u root --safe-updates

이렇게 켜면 WHERE 없는 UPDATE/DELETE 를 거부합니다.


11. 집계 함수 - 세기, 더하기, 평균

  SELECT COUNT(*)   FROM products;                몇 행인가
  SELECT COUNT(*)   FROM products WHERE stock = 0;   품절은 몇 개인가
  SELECT SUM(stock) FROM products;                재고 총합
  SELECT AVG(price) FROM products;                평균 가격
  SELECT MIN(price), MAX(price) FROM products;    가장 싼 것과 비싼 것

Day 12 에서 이렇게 했던 것입니다.

  save.reduce((sum, s) => sum + s.qty, 0)     ->  SELECT SUM(qty) ...

reduce 를 쓸 필요가 없습니다. 한 단어입니다.

⭐ COUNT(*) 와 COUNT(열이름) 은 다릅니다.

  COUNT(*)       행의 개수. NULL 이든 뭐든 다 센다
  COUNT(phone)   phone 이 NULL 이 아닌 행만 센다

  회원이 10명이고 그중 3명이 전화번호를 안 적었다면

  SELECT COUNT(*), COUNT(phone) FROM members;   ->   10,  7

이걸 모르고 COUNT(열) 을 쓰면 숫자가 조용히 틀립니다.
19번에서 NULL 얘기를 다시 합니다.

소수점을 정리하려면 ROUND 를 씁니다.

  SELECT ROUND(AVG(price))    FROM products;    4631
  SELECT ROUND(AVG(price), 2) FROM products;    4631.11


12. GROUP BY 와 HAVING - 묶어서 집계 ⭐⭐

"분류별로 몇 개씩 있나" 같은 질문입니다.

  SELECT kind, COUNT(*) AS 개수
  FROM products
  GROUP BY kind;

  ┌────────┬──────┐
  │ kind   │ 개수 │
  ├────────┼──────┤
  │ 필기구 │ 6    │
  │ 노트   │ 4    │
  │ 지우개 │ 3    │
  │ 파일   │ 3    │
  │ 테이프 │ 2    │
  └────────┴──────┘

GROUP BY kind 는 "kind 가 같은 행들을 한 덩어리로 묶어라" 는 뜻입니다.
묶은 다음 덩어리마다 COUNT(*) 를 셉니다.

여러 개를 한 번에 볼 수 있습니다.

  SELECT kind,
         COUNT(*)   AS 개수,
         SUM(stock) AS 재고합,
         ROUND(AVG(price)) AS 평균가,
         MAX(price) AS 최고가
  FROM products
  GROUP BY kind
  ORDER BY 개수 DESC;

⭐ WHERE 와 HAVING 의 차이가 시험에 잘 나옵니다.

  WHERE    묶기 **전에** 행을 거른다
  HAVING   묶은 **다음에** 덩어리를 거른다

  SELECT kind, COUNT(*) AS 개수
  FROM products
  WHERE stock > 0          <- 품절이 아닌 상품만 데려와서
  GROUP BY kind
  HAVING COUNT(*) >= 3     <- 묶어보니 3개 이상인 분류만 남긴다
  ORDER BY 개수 DESC;

WHERE 에는 COUNT(*) 를 쓸 수 없습니다. 아직 세지 않았으니까요.
실행 순서가 이렇게 정해져 있습니다.

  FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY -> LIMIT

이 순서를 외워두면 "왜 여기선 별명을 못 쓰지?" 같은 의문이 풀립니다.
SELECT 에서 만든 별명(AS 개수)을 WHERE 에서는 못 씁니다. WHERE 가 먼저니까요.
ORDER BY 에서는 쓸 수 있습니다. 나중이니까요.


13. 외래키 - 표와 표를 잇기

order_items.product_id 에는 products.id 에 있는 값만 들어와야 합니다.
없는 상품 번호가 들어가면 주문서가 망가집니다.

Day 12 에서 겪은 그 함정입니다. 저장값에 zzz 라는 없는 id 를 심었더니
합계가 NaN 이 됐죠. 그때는 clean() 함수를 만들어서 코드로 걸렀습니다.
데이터베이스는 **애초에 못 들어오게** 막을 수 있습니다.

  FOREIGN KEY (product_id) REFERENCES products(id)

이걸 걸어두면

  INSERT INTO order_items (order_id, product_id, qty, price)
  VALUES (1, 9999, 2, 600);

  ERROR 1452: Cannot add or update a child row:
              a foreign key constraint fails

거부됩니다. 코드에 버그가 있어도 데이터는 안 망가집니다.

지울 때 어떻게 할지도 정해둡니다.

  ┌───────────────────────────┬───────────────────────────────┐
  │ 설정                      │ 부모를 지우면                 │
  ├───────────────────────────┼───────────────────────────────┤
  │ ON DELETE RESTRICT (기본) │ 자식이 있으면 못 지운다       │
  │ ON DELETE CASCADE         │ 자식도 같이 지운다            │
  │ ON DELETE SET NULL        │ 자식의 그 열을 NULL 로 만든다 │
  └───────────────────────────┴───────────────────────────────┘

주문을 지우면 그 주문의 상세는 남아 있을 이유가 없습니다. 그래서 CASCADE.
상품을 지울 때는 과거 주문 기록이 사라지면 안 됩니다. 그래서 기본값(RESTRICT).
위의 CREATE TABLE 을 다시 보면 그렇게 적혀 있습니다.


14. JOIN - 두 표를 붙여서 보기 ⭐⭐⭐

여기가 SQL 의 핵심입니다. 그리고 대회에서 반드시 나옵니다.

order_items 를 그냥 꺼내면 숫자만 나옵니다.

  SELECT * FROM order_items WHERE order_id = 1;

  ┌────┬──────────┬────────────┬─────┬───────┐
  │ id │ order_id │ product_id │ qty │ price │
  ├────┼──────────┼────────────┼─────┼───────┤
  │ 1  │ 1        │ 1          │ 2   │ 600   │
  │ 2  │ 1        │ 5          │ 1   │ 3400  │
  └────┴──────────┴────────────┴─────┴───────┘

사람이 볼 화면에는 상품 **이름**이 나와야 합니다. 이름은 products 에 있습니다.
두 표를 이어서 봐야 합니다. 이을 수 있는 이유는 양쪽에 같은 값이 있기 때문입니다.
order_items.product_id 와 products.id 가 그 연결고리입니다.

  SELECT oi.qty, oi.price, p.name, p.brand
  FROM order_items AS oi
  JOIN products    AS p ON oi.product_id = p.id
  WHERE oi.order_id = 1;

  ┌─────┬───────┬────────────────────────┬──────────┐
  │ qty │ price │ name                   │ brand    │
  ├─────┼───────┼────────────────────────┼──────────┤
  │ 2   │ 600   │ 모나미 153 볼펜 0.7    │ 모나미   │
  │ 1   │ 3400  │ 옥스포드 스프링노트 A5 │ 옥스포드 │
  └─────┴───────┴────────────────────────┴──────────┘

ON 뒤에 적은 것이 "무엇으로 이을까" 입니다. 여기를 틀리면 결과가 폭발합니다.
AS oi, AS p 는 표 별명입니다. 길게 쓰기 귀찮아서 붙입니다.
열 이름이 양쪽에 겹칠 때(id 처럼) 어느 표의 것인지 밝혀야 하니 별명이 필요합니다.

세 개도 붙일 수 있습니다. 회원 이름까지 보려면

  SELECT m.name AS 회원, o.ordered_at, p.name AS 상품, oi.qty, oi.price
  FROM orders AS o
  JOIN members     AS m  ON o.member_id = m.id
  JOIN order_items AS oi ON oi.order_id = o.id
  JOIN products    AS p  ON oi.product_id = p.id
  WHERE o.id = 1;

⭐ INNER JOIN 과 LEFT JOIN 의 차이 - 이걸 꼭 알아야 합니다

  JOIN (= INNER JOIN)   양쪽에 다 있는 것만 나온다
  LEFT JOIN             왼쪽은 다 나온다. 오른쪽에 없으면 NULL 로 채운다

"회원별 주문 건수" 를 뽑아봅시다. 주문을 한 번도 안 한 회원이 있다고 하고요.

  SELECT m.name, COUNT(o.id) AS 주문수
  FROM members AS m
  JOIN orders  AS o ON o.member_id = m.id
  GROUP BY m.id;

이러면 **주문 안 한 회원은 아예 안 나옵니다.** 명단에서 사라집니다.

  SELECT m.name, COUNT(o.id) AS 주문수
  FROM members   AS m
  LEFT JOIN orders AS o ON o.member_id = m.id
  GROUP BY m.id;

  ┌──────┬────────┐
  │ name │ 주문수 │
  ├──────┼────────┤
  │ 노벨 │ 3      │
  │ 지민 │ 1      │
  │ 수아 │ 0      │
  └──────┴────────┘

수아가 0 으로 나옵니다. 이게 보통 원하는 결과입니다.

여기서 COUNT(o.id) 를 쓴 것이 중요합니다. COUNT(*) 를 쓰면 수아가 1 이 됩니다.
LEFT JOIN 이 NULL 로 채운 **행 하나**가 있으니까요. COUNT(*) 는 그 행을 세고,
COUNT(o.id) 는 o.id 가 NULL 이라서 안 셉니다. 11번의 그 차이가 여기서 터집니다.

⚠️ JOIN 하고 나서 WHERE 로 오른쪽 표를 거르면 LEFT JOIN 이 무의미해집니다.

  LEFT JOIN orders AS o ON o.member_id = m.id
  WHERE o.status = '결제'      <- 여기서 NULL 행이 전부 탈락한다

오른쪽 조건은 ON 에 붙이세요.

  LEFT JOIN orders AS o ON o.member_id = m.id AND o.status = '결제'


15. 서브쿼리 - 쿼리 안에 쿼리

괄호로 감싼 SELECT 를 값처럼 씁니다. 세 자리에 쓸 수 있습니다.

  (가) WHERE 안에서 - 가장 많이 씁니다

  SELECT name, price FROM products
  WHERE price > (SELECT AVG(price) FROM products);

  평균보다 비싼 상품. 평균을 먼저 구해서 손으로 적을 필요가 없습니다.

  SELECT name FROM products
  WHERE id IN (SELECT DISTINCT product_id FROM order_items);

  한 번이라도 팔린 상품. 반대로 안 팔린 상품은 NOT IN 입니다.

  (나) SELECT 안에서 - 행마다 계산

  SELECT m.name,
         (SELECT COUNT(*) FROM orders o WHERE o.member_id = m.id) AS 주문수
  FROM members AS m;

  LEFT JOIN + GROUP BY 로 한 것과 같은 결과입니다. 읽기는 쉽지만 보통 느립니다.

  (다) FROM 안에서 - 결과를 임시 표로

  SELECT kind, AVG(합계) FROM (
    SELECT kind, SUM(price * stock) AS 합계
    FROM products GROUP BY kind, brand
  ) AS t
  GROUP BY kind;

  집계한 결과를 다시 집계할 때 씁니다. FROM 안에 쓸 때는 AS 별명이 필수입니다.

⚠️ NOT IN 과 NULL 을 같이 쓰면 결과가 통째로 비어버립니다.

  SELECT name FROM products WHERE id NOT IN (SELECT product_id FROM order_items);

  order_items.product_id 에 NULL 이 하나라도 있으면 **아무것도 안 나옵니다.**
  NULL 과 비교한 결과는 참도 거짓도 아니기 때문입니다 (19번).
  NOT EXISTS 를 쓰면 안전합니다.

  SELECT name FROM products AS p
  WHERE NOT EXISTS (SELECT 1 FROM order_items oi WHERE oi.product_id = p.id);


16. 중복 처리 - 있으면 고치고 없으면 넣기

장바구니를 생각해보세요. Day 12 에서 이렇게 했습니다.

  const already = save.find(s => s.id === id)
  if (already) already.qty++
  else save.push({ id, qty: 1 })

SQL 에는 이걸 한 문장으로 하는 방법이 있습니다. 먼저 UNIQUE 가 있어야 합니다.

  ALTER TABLE order_items ADD UNIQUE (order_id, product_id);

열 두 개를 묶어서 UNIQUE 를 걸었습니다. "같은 주문에 같은 상품은 한 줄만" 이라는 뜻입니다.
그 다음

  INSERT INTO order_items (order_id, product_id, qty, price)
  VALUES (1, 3, 1, 1800)
  ON DUPLICATE KEY UPDATE qty = qty + 1;

없으면 새 줄로 들어가고, 이미 있으면 qty 를 1 늘립니다. 조회를 먼저 할 필요가 없습니다.

  INSERT IGNORE INTO ...      이미 있으면 조용히 넘어간다
  REPLACE INTO ...            이미 있으면 지우고 새로 넣는다 (⚠️ 다른 열도 날아감)

REPLACE 는 조심하세요. 지우고 다시 넣는 것이라서 적지 않은 열이
DEFAULT 로 돌아가고, AUTO_INCREMENT id 도 바뀝니다. 거의 안 씁니다.


17. 인덱스 - 왜 빠른가

책에서 어떤 단어를 찾을 때, 처음부터 한 장씩 넘기면 오래 걸립니다.
뒤에 있는 찾아보기(색인)를 보면 몇 페이지인지 바로 나옵니다. 그게 인덱스입니다.

인덱스가 없으면 데이터베이스는 **모든 행을 하나씩 다 봅니다.**
행이 10개면 상관없고 100만 개면 느립니다.

  CREATE INDEX idx_products_kind ON products(kind);
  CREATE INDEX idx_oi_order      ON order_items(order_id);

PRIMARY KEY 와 UNIQUE 는 인덱스가 자동으로 생깁니다. 따로 안 만들어도 됩니다.

  ┌───────────────────────┬─────────────────────────────┐
  │ 여기에 걸면 좋다      │ 이유                        │
  ├───────────────────────┼─────────────────────────────┤
  │ WHERE 에 자주 쓰는 열 │ 거르는 일이 빨라진다        │
  │ JOIN 의 ON 에 쓰는 열 │ 외래키 쪽은 거의 필수       │
  │ ORDER BY 에 쓰는 열   │ 정렬을 안 하고 꺼낼 수 있다 │
  └───────────────────────┴─────────────────────────────┘

⚠️ 많이 걸면 좋은 게 아닙니다. INSERT/UPDATE 할 때마다 인덱스도 고쳐야 하니
   쓰기가 느려지고 용량도 먹습니다. 꺼낼 때 쓰는 열에만 거세요.

⚠️ LIKE '%볼펜%' 처럼 앞에 % 가 붙으면 인덱스를 못 씁니다.
   '모나미%' 처럼 뒤에만 붙으면 쓸 수 있습니다. 색인이 가나다순으로
   정렬돼 있어서, 시작 글자를 모르면 색인을 볼 수 없는 것과 같습니다.

내 쿼리가 인덱스를 쓰는지 보려면 앞에 EXPLAIN 을 붙입니다.

  EXPLAIN SELECT * FROM products WHERE kind = '노트';

type 칸에 ALL 이 나오면 전부 훑는 것이고, ref 나 const 가 나오면 인덱스를 쓴 것입니다.


18. 트랜잭션 - 전부 되거나 전부 안 되게 ⭐⭐

주문을 넣을 때 할 일이 세 개입니다.

  1) orders 에 주문 한 줄 넣기
  2) order_items 에 담긴 상품들 넣기
  3) products 의 stock 을 깎기

2번까지 하고 3번에서 에러가 나면? 주문은 들어갔는데 재고는 그대로입니다.
데이터가 어긋난 상태로 남습니다. 이걸 막는 게 트랜잭션입니다.

  START TRANSACTION;

    INSERT INTO orders (member_id) VALUES (1);
    INSERT INTO order_items (order_id, product_id, qty, price)
      VALUES (LAST_INSERT_ID(), 1, 2, 600);
    UPDATE products SET stock = stock - 2 WHERE id = 1;

  COMMIT;

COMMIT 을 하기 전까지는 아무것도 확정되지 않습니다.
중간에 문제가 생기면

  ROLLBACK;

하면 START TRANSACTION 이후의 모든 변경이 없던 일이 됩니다.

LAST_INSERT_ID() 는 방금 넣은 행의 AUTO_INCREMENT id 입니다.
주문을 넣고 그 주문 번호를 바로 써야 하니 필요합니다.
`db.php` 의 "exec" => LastInsertid() 가 이걸 PHP 에서 받는 것입니다.

⚠️ CREATE TABLE, ALTER TABLE, DROP 같은 문장은 ROLLBACK 이 안 됩니다.
   트랜잭션 안에 있어도 바로 확정됩니다. 되돌릴 수 있는 건 INSERT/UPDATE/DELETE 입니다.

⚠️ MyISAM 엔진은 트랜잭션을 지원하지 않습니다. InnoDB 를 쓰세요.
   요즘은 기본값이 InnoDB 라서 신경 쓸 일이 거의 없지만, 확인은 이렇게 합니다.

  SHOW TABLE STATUS WHERE Name = 'orders';


19. NULL 의 함정 ⭐

NULL 은 0 도 아니고 빈 문자열도 아닙니다. **"값이 없음"** 입니다.
모르는 값이라서, 비교하면 참도 거짓도 아닌 "알 수 없음" 이 나옵니다.

  ┌───────────────────┬──────────────────┬──────────────────────────────────────┐
  │ 쓴 것             │ 결과             │ 설명                                 │
  ├───────────────────┼──────────────────┼──────────────────────────────────────┤
  │ phone = NULL      │ 아무것도 안 나옴 │ NULL 과는 = 로 비교할 수 없다        │
  │ phone IS NULL     │ 제대로 나옴      │ 이게 맞는 방법                       │
  │ phone <> '010'    │ NULL 행은 빠진다 │ NULL 은 다르다고도 판정되지 않는다   │
  │ COUNT(phone)      │ NULL 은 안 센다  │ COUNT(*) 와 숫자가 달라진다          │
  │ SUM(price)        │ NULL 은 건너뛴다 │ 다 NULL 이면 결과도 NULL (0 이 아님) │
  │ NULL + 1          │ NULL             │ 계산에 NULL 이 끼면 전부 NULL        │
  │ CONCAT('a', NULL) │ NULL             │ 글자 이어붙이기도 NULL 로 오염된다   │
  └───────────────────┴──────────────────┴──────────────────────────────────────┘

NULL 을 다른 값으로 바꿔서 받으려면 IFNULL 이나 COALESCE 를 씁니다.

  SELECT IFNULL(phone, '미등록') FROM members;
  SELECT COALESCE(phone, mobile, '연락처 없음') FROM members;

COALESCE 는 여러 개 중에 처음으로 NULL 이 아닌 값을 고릅니다.
JS 의 ?? 연산자와 같은 일입니다. Day 12 에서 read 함수에 fallback 을 둔 그 생각입니다.

  JS    JSON.parse(x) ?? []
  SQL   IFNULL(합계, 0)

⚠️ 그래서 "값이 없음" 과 "0" 을 구분할 필요가 없으면 애초에 NOT NULL DEFAULT 0
   으로 만들어 두는 게 편합니다. 위의 products.stock 이 그렇게 돼 있습니다.


20. 심화 맛보기 - 윈도 함수와 CTE

MariaDB 10.2 부터 쓸 수 있습니다. 이 컴퓨터는 10.4 라서 됩니다.
대회에서 꼭 필요한 건 아니지만, 알면 한 방에 끝나는 문제가 있습니다.

  (가) 윈도 함수 - 묶지 않고 순위 매기기

GROUP BY 는 여러 행을 한 줄로 **접습니다.** 윈도 함수는 **안 접고** 옆에 값을 붙입니다.

  SELECT name, kind, price,
         RANK() OVER (PARTITION BY kind ORDER BY price DESC) AS 분류내순위
  FROM products;

  ┌────────────────────────┬────────┬───────┬────────────┐
  │ name                   │ kind   │ price │ 분류내순위 │
  ├────────────────────────┼────────┼───────┼────────────┤
  │ 파버카스텔 색연필 24색 │ 필기구 │ 18000 │ 1          │
  │ 제브라 마일드라이너    │ 필기구 │ 7500  │ 2          │
  │ 파버카스텔 그립 연필   │ 필기구 │ 5200  │ 3          │
  │ 옥스포드 다이어리 2027 │ 노트   │ 12500 │ 1          │
  │ 옥스포드 스프링노트 A5 │ 노트   │ 3400  │ 2          │
  └────────────────────────┴────────┴───────┴────────────┘

PARTITION BY 가 "분류별로 따로 순위를 매겨라" 입니다. GROUP BY 와 달리 행이 안 줄어듭니다.

  ROW_NUMBER()   1, 2, 3, 4      동점도 다른 번호
  RANK()         1, 2, 2, 4      동점은 같은 번호, 다음은 건너뜀
  DENSE_RANK()   1, 2, 2, 3      동점은 같은 번호, 건너뛰지 않음
  SUM(x) OVER    누적 합계

  (나) CTE - 쿼리에 이름 붙이기

FROM 안의 서브쿼리를 위로 꺼내서 이름을 붙인 것입니다. 읽기가 훨씬 쉽습니다.

  WITH 분류별 AS (
    SELECT kind, COUNT(*) AS 개수, SUM(price * stock) AS 재고금액
    FROM products
    GROUP BY kind
  )
  SELECT * FROM 분류별 WHERE 개수 >= 3 ORDER BY 재고금액 DESC;

같은 CTE 를 아래에서 여러 번 쓸 수 있습니다. 서브쿼리는 쓸 때마다 적어야 합니다.


21. PHP 에서 쓸 때 ⭐⭐⭐ 가장 중요합니다

SQL 을 문자열로 이어붙이면 안 됩니다. 절대로요.

  ❌ 이렇게 하면 뚫립니다

  $id = $_GET['id'];
  $sql = "SELECT * FROM members WHERE login_id = '$id'";

누가 id 에 이런 걸 넣으면

  ' OR '1'='1

문장이 이렇게 됩니다.

  SELECT * FROM members WHERE login_id = '' OR '1'='1'

조건이 항상 참이라서 **회원 전체가 나옵니다.** 로그인도 그냥 통과합니다.
더 넣으면 표를 지울 수도 있습니다. 이게 SQL 인젝션입니다.

  ✅ 자리표시자를 씁니다

  $st = $db->prepare("SELECT * FROM members WHERE login_id = ?");
  $st->execute([$_GET['id']]);
  $row = $st->fetch();

? 자리에 값이 **데이터로** 들어갑니다. 따옴표가 섞여 있어도 문장 구조가 안 바뀝니다.
이름을 붙일 수도 있습니다.

  $st = $db->prepare("SELECT * FROM members WHERE login_id = :id AND name = :name");
  $st->execute([':id' => $a, ':name' => $b]);

php-study 에 이미 있는 MVC_PATTERN/db.php 가 이걸 감싸둔 것입니다.

  DB::fetch("SELECT * FROM members WHERE login_id = ?", [$id]);
  DB::fetchAll("SELECT * FROM products WHERE kind = ?", [$kind]);
  DB::exec("INSERT INTO orders (member_id) VALUES (?)", [$mid]);   // id 를 돌려준다
  DB::run("UPDATE products SET stock = stock - ? WHERE id = ?", [$n, $id]);

두 번째 인자인 배열이 자리표시자에 들어갈 값들입니다.
**열 이름과 표 이름은 자리표시자로 못 바꿉니다.** 값만 됩니다.

  ❌ DB::fetchAll("SELECT * FROM products ORDER BY ?", [$sort]);

정렬 기준을 사용자가 고르게 하려면, 받은 값을 그대로 넣지 말고
허용 목록에서 골라야 합니다. Day 12 에서 sort 값이 default/name/cheap/expensive
네 개뿐이었던 것처럼요.


22. 대회에서 나오는 모양

C모듈이 PHP + 데이터베이스입니다. 과제서에 ERD(표 관계 그림)와
테이블 명세가 주어지고, 그대로 만들어서 기능을 붙이는 식입니다.

자주 나오는 것들입니다.

  · 목록 + 검색 + 분류 + 정렬 + 페이지 나누기     SELECT WHERE ORDER BY LIMIT
  · 상세 보기                                     WHERE id = ?
  · 등록 / 수정 / 삭제                            INSERT UPDATE DELETE
  · 회원가입 중복 체크                            UNIQUE 또는 COUNT(*)
  · 로그인                                        WHERE login_id = ? + 비밀번호 검증
  · 통계 화면 (분류별 개수, 월별 합계)             GROUP BY
  · 주문/예약처럼 표 두 개를 같이 건드리는 것      트랜잭션
  · 목록에 다른 표의 이름을 같이 보여주기          JOIN

Day 12 에서 만든 장바구니가 그대로 C모듈 과제 모양입니다.
그때는 localStorage 에 담았고, 이제는 데이터베이스에 담습니다.

⚠️ 기억해둘 것 - 확인된 채점 기준에서 **구현 방법은 채점하지 않습니다.**
   코드 품질로 점수가 붙는 항목은 주석(한글) 2점이 유일합니다.
   그러니 "멋있게" 짜는 데 시간을 쓰지 말고 **동작하게** 만드는 데 쓰세요.
   다만 느려서 화면이 안 뜨면 그건 동작하지 않는 것이니, 인덱스와 JOIN 은
   제대로 알아야 합니다.


=== 외울 것 ===

  실행 순서    FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY -> LIMIT
               SELECT 의 별명(AS)은 WHERE 에서 못 쓰고 ORDER BY 에서는 쓴다

  WHERE        묶기 전에 행을 거른다
  HAVING       묶은 다음 덩어리를 거른다. COUNT 같은 집계는 여기서만

  JOIN         양쪽에 다 있는 것만
  LEFT JOIN    왼쪽은 다 나온다. 없는 쪽은 NULL
               LEFT JOIN 뒤에 오른쪽 조건을 WHERE 에 쓰면 LEFT 가 무의미해진다

  COUNT(*)     행을 센다
  COUNT(열)    그 열이 NULL 이 아닌 것만 센다. 숫자가 조용히 달라진다

  NULL         = 로 비교 못 한다. IS NULL / IS NOT NULL
               계산에 끼면 결과도 NULL. IFNULL 로 막는다

  UPDATE/DELETE 는 WHERE 를 먼저 쓴다. 같은 WHERE 로 SELECT 를 먼저 해본다

  LIMIT 을 쓸 거면 ORDER BY 를 같이 쓴다. 안 쓰면 순서가 보장되지 않는다

  트랜잭션     START TRANSACTION -> ... -> COMMIT (또는 ROLLBACK)
               CREATE/ALTER/DROP 은 ROLLBACK 이 안 된다

  PHP          문자열을 이어붙이지 않는다. 자리표시자 ? 를 쓴다
               값만 자리표시자로 넣을 수 있다. 열 이름과 표 이름은 안 된다

  한글이 깨지면 utf8mb4 를 확인한다
